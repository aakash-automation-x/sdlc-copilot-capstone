High — Claude Code syntax leaked into Copilot files

H-01
subagent_type: key is Claude Code SDK syntax, not Copilot
.github/agents/orchestrator.agent.md : 168

Issue

Line 168: "Invoking Architect Agent (subagent_type: 'Architect Agent') to design...". The subagent_type parameter is part of the Claude Code SDK's Agent() function call — it has no meaning in GitHub Copilot. Copilot agents are selected by the user in the Chat agent picker; no programmatic invocation API exists.

Fix

Remove (subagent_type: 'Architect Agent'). Replace with Copilot-idiomatic guidance: "Tell the user to switch to the Architect Agent in the Copilot Chat agent picker to continue."
H-02
"Claude Capabilities Used" section references non-existent "Agent tool"
.github/agents/orchestrator.agent.md : 174–180

Issue

Section header reads "Claude Capabilities Used"; the body states "Orchestrator invokes each pipeline agent in order via the Agent tool using their name: values." GitHub Copilot has no "Agent tool" — that is the Claude Code SDK's Agent() function. In Copilot, agents are selected by the user in the Chat picker or routed via description matching; the orchestrator cannot invoke other agents programmatically.

Fix

Rename section to "GitHub Copilot Capabilities Used". Replace the "Agent tool" bullet with: "Agents are invoked by asking the user to select the next pipeline agent in the GitHub Copilot Chat agent picker."
H-03
Example output shows subagent_type: — Copilot never produces this text
.github/prompts/00-orchestrator.prompt.md : 98, 127

Issue

The "Example Flow" section shows expected orchestrator output as:
Orchestrator: Invoking Requirements Agent (subagent_type: "Requirements Agent")...
and (subagent_type: "Architect Agent") on line 127. This sets incorrect expectations — Copilot will not produce this output. subagent_type is a Claude Code SDK parameter.

Fix

Remove (subagent_type: "...") from both lines. Use Copilot-idiomatic language, e.g.: "→ Step 1 complete. Please switch to the Requirements Agent in the agent picker to begin."

Medium — Spec violations and internal contradictions

M-01
ORCHESTRATION_LOG.md missing artifacts/ prefix in 8 places
copilot-instructions.md : 51 · 00-orchestrator.prompt.md : 55, 81, 124, 191, 198

Issue

orchestrator.agent.md consistently and correctly uses artifacts/ORCHESTRATION_LOG.md. In contrast, copilot-instructions.md (line 51) and 00-orchestrator.prompt.md (6 occurrences) use the bare path ORCHESTRATION_LOG.md. An agent reading the prompt file could write the log to the repo root instead of the artifacts/ directory.

Fix

Replace all 8 bare occurrences with artifacts/ORCHESTRATION_LOG.md. Note: line 26 of copilot-instructions.md already uses the full path — use it as the canonical reference.
M-02
model: claude-sonnet-4-6 is not a recognized GitHub Copilot model ID
All 9 .github/agents/*.agent.md — line 8

Issue

VS Code Copilot extension raises "Unknown model 'claude-sonnet-4-6' will be ignored" on all 9 agent files. claude-sonnet-4-6 is the Claude Code CLI's own runtime model ID — it is not a valid GitHub Copilot model identifier. The model: field silently falls through to Copilot's default, making the declaration misleading without providing any actual control.

Fix

Remove the model: field from all 9 agent files to defer to Copilot's default model. If a specific Claude model is needed, verify the correct GitHub Copilot model ID in the VS Code Copilot settings (GitHub Copilot model IDs differ from Anthropic API IDs).
M-03
Body says "single, core behavior" but description allows multiple requirements
.github/skills/write-requirements/SKILL.md — Step 1.2, Rules table

Issue

The frontmatter description says "Extract functional requirements" (plural) and Step 2 says "Prefer one; add more only when the story explicitly requires multiple." But Step 1.2 contradicts both: "Extract the primary functional requirement — the single, core behavior." The Rules table doubles down: "FR statement: one behavior only." The Requirements Agent receives conflicting guidance on whether to produce one or multiple FRs.

Fix

Update Step 1.2 to: "Extract the minimum complete set of functional requirements — prefer one, but include more only when the story explicitly requires distinct behaviors." Update the Rules table row to: "FR statement: independently testable; one behavior per requirement."
M-04
"rules" is Claude Code terminology — Copilot uses "instructions"
.github/skills/design-review/SKILL.md : 43 · design-architecture/SKILL.md : 53

Issue

Both skills contain the phrase "agents, prompts, rules, skills, and hooks." In GitHub Copilot the analogous config files are instructions (.github/instructions/*.instructions.md). The term "rules" belongs to Claude Code's .claude/rules/ directory and has no meaning in Copilot. A reviewer applying this checklist would look for the wrong files.

Fix

Replace "rules" with "instructions" in both files: "agents, prompts, instructions, skills, and hooks."

L-02
sdlc-artifacts.instructions.md does not cover ORCHESTRATION_LOG.md

Issue

The applyTo field lists 5 artifact paths (requirements.md, architecture.md, design-review.md, impl-plan.md, CHANGELOG.md) but omits artifacts/ORCHESTRATION_LOG.md, which is the primary pipeline state file. Artifact writing standards don't apply when the orchestrator writes or updates the log.
