H-01 — `handoffs` is not a valid GitHub Copilot agent frontmatter field
High Invalid Metadata All 9 agent files
Every agent file declares a handoffs: array in its YAML frontmatter (e.g., handoffs: [requirements, architect, design-review, ...]). GitHub Copilot's agent specification only recognizes name, description, tools, and model as frontmatter keys. The handoffs field is silently ignored by Copilot — it does not create any routing or sequencing behavior. The field originated from a Claude Code agent convention.
Fix: Remove the handoffs: field from all agent frontmatter. Document intended handoff targets in the agent body text instead, e.g., "Hand off to the Architect Agent (Step 2) once complete."
H-02 — Tool names are Claude Code identifiers, not GitHub Copilot tools
High Invalid Metadata All 9 agent files
All agent files declare tools: ["Bash", "Read", "Edit", "Write", "Glob", "Grep", "Agent"]. These are Claude Code tool names. GitHub Copilot's agent tool identifiers are different: codebase (search), editFiles, runInTerminal, webSearch, readFile, createFile, etc. Copilot will not recognize Bash, Glob, or Agent as valid tools. The Agent tool in particular is a Claude Code-exclusive construct.
Fix: Replace tool names with GitHub Copilot equivalents. For example: Bash → runInTerminal, Read → readFile, Edit/Write → editFiles, Glob/Grep → codebase. Remove the Agent tool entirely — Copilot does not support it.
H-03 — Model identifiers are Anthropic API names, not GitHub Copilot model IDs
High Invalid Metadata Files: 6 agent files
Six agents declare model: claude-sonnet-4-6 and three use model: claude-haiku-4-5-20251001. These are Anthropic direct API model identifiers. Copilot may not resolve claude-sonnet-4-6 or claude-haiku-4-5-20251001 and could fall back to a default or produce an error.

H-04 — Orchestrator uses Claude Code `Agent({...})` tool invocation syntax
High Incorrect Convention File: agents/orchestrator.agent.md:82–88
Lines 82–88 of orchestrator.agent.md instruct the agent to call subagents using Agent({ subagent_type: "Requirements Agent", ... }). This is Claude Code's internal Agent tool API. GitHub Copilot does not have an equivalent Agent() function call. In Copilot's agentic model, one agent cannot programmatically invoke another agent by name at runtime — coordination happens through conversation context, prompts, and chained invocations by the user or orchestrator prompt.
Fix: Replace the Agent({...}) call instructions with explicit Copilot-compatible phrasing, e.g., instruct the orchestrator to present the next step and prompt the user to invoke the named agent manually, or restructure the orchestrator as a prompt file (mode: agent) that uses agent tool calls natively if/when Copilot supports multi-agent chaining.
H-05 — Orchestrator prompt missing `mode: agent` frontmatter
High Missing Metadata File: prompts/00-orchestrator.prompt.md
The orchestrator prompt file's frontmatter contains only description. GitHub Copilot prompt files support a mode field (ask, edit, or agent) that controls how the prompt is executed. Without mode: agent, the prompt defaults to ask (chat) mode, which means tools and file operations are not available — exactly what the orchestrator needs to run the pipeline. It also supports a tools field to explicitly declare which tools the prompt may use.
Fix: Add mode: agent and a tools list to the prompt frontmatter: mode: agent, tools: [codebase, editFiles, runInTerminal].
